# Breakwater interaction audio sources

The editable [layer session](breakwater.json) defines 52 mono cue and loop variants for the benchmark. It replaces generic laser/jingle mappings with separate recorded treatments for sidearm, HMG, rifle, shotgun, tank gun, armor, grenade, footsteps, boarding, exit, ejection and lock-engine interactions. The two persistent loops contain 115,200 and 76,800 frames at 48 kHz: 2.4 seconds of engine pulses and 1.6 seconds of flame air. Runtime playback adds spatial placement and bounded identity-based variation.

Fourteen original files from [Kenney Impact Sounds](https://kenney.nl/assets/impact-sounds) remain byte-for-byte in `kenney/`, with the pack's [CC0 license](kenney/License.txt). These upstream originals are Vorbis recordings. Exporting derived lossless masters does not recover information discarded by the original encoding. Four existing lossless VSCO CE instrument sources supply drum body, cymbal air and marimba interaction notes. [Provenance](provenance.json) retains archive/source URLs, creators, license paths, exact sizes and hashes. The authored layer arrangements follow the repository license; the source recordings retain their CC0 dedication.

Run `pnpm audio:sfx:render` with the mise-owned Node and FFmpeg tools. Each layer has an explicit sample, start, trim, playback rate, gain, envelope and optional frequency filters. The renderer trims initial source silence, mixes those recorded layers and wraps tails only for declared loops. It writes PCM24 FLAC masters to `../masters/sfx/` and Vorbis quality-5 runtime exports to `public/assets/audio/sfx/`. Bit-exact Ogg muxing fixes the stream identity; explicit 20 ms pages prevent the short-file decode length loss found during validation. The original source and every derived master remain checked in.

`pnpm audio:validate` verifies source/license fingerprints, source-to-export metadata, master/runtime hashes, mono 48 kHz lengths, headroom, non-silence, decoded loop seams and budgets. An independent second render produces identical bytes for all 106 master/runtime/manifest outputs with the installed toolchain. The 52 runtime variants total 383,694 bytes compressed and 3,762,240 bytes decoded. These are measured source/render results, not a claim of identical output across different encoder versions.

The [typed cue policy](../../../src/shared/animation/sfx-profile.ts) declares variants, gain/rate ranges, per-emitter cooldowns, spatial range, priorities and simultaneous limits. [Accepted-state selectors](../../../src/shared/animation/combat-audio.ts) own ignition/stop intents and engine/flame presence. The renderer admits 32 audible SFX voices including up to eight persistent loops; music has a separate bus. During a steal, the outgoing source fades for 5 ms before the replacement starts, so temporary scheduled/retiring graph nodes do not increase audible overlap. Both music and SFX pass through the same output and capture path, with an overload knee that leaves ordinary levels unchanged.

Run `pnpm test:audio:combat` for real Chromium decoding, three repeats of both loops, current-state reconstruction, ejection, mute/pause/reset/disposal, duplicate suppression, a 32-voice stress mix and the cue comparison. The harness explicitly uses `--disable-audio-output` because the earlier WSL audio-device clock problem remains unresolved. WebAudio and MediaRecorder still render the signal; physical-device output and human listening quality remain unverified. See the [implementation evidence](../../../docs/redesign-evidence/W06-interaction-audio.md).

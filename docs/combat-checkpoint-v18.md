# Diagnostic combat archive format 18

Archive 18 and combat simulation/recording format 15 add the tank cannon to protocol 3.15. Combat snapshot section 5, Breakwater mission/recording format 5 and material recording format 2 retain their layouts; their content identities change. Earlier experimental wire/archive/combat formats and content identities are rejected.

Each tank retains its finite secondary ammunition, shots spent, cooldown, shot ordinal, last action ID and independent action clock. Private state also retains the last cannon owner and that owner's input generation. Its ten depot shells are conserved: ammunition plus shots spent equals ten. A shell is spent when a Grenade edge starts the action. Cancellation before release does not refund it. Cooldown requests and empty requests allocate nothing.

The twelve-tick action locks one of eight authored headings, releases once at offset three, then recoils visually. The primary hardpoint continues independently. Both hardpoints share a monotonically increasing shot-ordinal space while retaining their own latest ordinal, action and attribution. Checkpoint validation rejects conflicting hardpoint identities, forged stock, incorrect marker cursors, impossible cooldown phase and mismatched owner generations.

Released cannon shells use the existing ballistic projectile record with attack definition 19, an 8-by-8 flight body and one 56-pixel-radius contact blast. Cardinal velocity is 12 pixels per tick and diagonal velocity is 8 pixels per axis. Flight uses exact swept contact against physical terrain, shields and opposing bodies. The blast owns the complete six-point damage budget; direct contact contributes zero additional damage. Existing material damage and occlusion policies apply to the blast. The shell expires without a blast after ninety flight ticks if it never contacts anything.

Snapshots carry the full public secondary state, including its action clock, plus shell position, velocity and heading. Shell identity, original owner, action and birth tick remain private continuation state. Exit, disconnect, empty-room settlement and destruction cancel unreleased actions while preserving released shells. Resuming a checkpoint or accepted journal does not spend another shell or repeat its release marker.

The cannon fixture covers solo and four-player admission, duplicate packets, simultaneous primary/cannon input, airborne release, a second shell, a paid third shell canceled by exit, and fifteen wire/checkpoint/journal boundaries per party size. SQLite verification restores sixteen four-player boundaries in fresh processes, injecting transaction rollback before each journal commit. Browser evidence is recorded separately; local workerd results do not establish deployed timing or live trace ingestion.

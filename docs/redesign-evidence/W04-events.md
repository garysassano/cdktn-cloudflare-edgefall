# W04: acknowledged combat events and explicit prefix repair

The diagnostic combat room now sends a bounded binary event stream alongside its full snapshots. Its history/cursor commit with the accepted world/input transaction. The client acknowledges a contiguous consumed prefix, deduplicates repeated records, and installs a specifically promised full snapshot when the retained prefix is unavailable. This extends the earlier [world transaction proof](./W04-world-transaction.md); production remains v2 and W04/G2 is open.

## Implemented boundary

The [event contract](../events-v3.md) defines capability `3`, a 32-byte batch header and 60-byte records, at most 64 records/3,872 bytes per frame. Stable event identities are `(runEpoch, tick, counter)`; delivery uses a separate monotonic cursor. Firearm confirmations carry player/control-epoch/shot-ordinal keys across all markers of an action. The server retains at most 120 ticks/512 records, with separate ordinary-age and capacity-eviction counts. An event validation/encoding failure cannot publish the candidate world or consume its inputs.

For normal delivery the room replays the retained suffix after the client's acknowledgment. A missing prefix sends `resync-required`, a paired input mapping and a full snapshot with an exact tick/cursor promise. Event/snapshot publication pauses for that reader until it acknowledges that snapshot and cursor together. Older in-flight acknowledgments remain valid. A client-detected gap sends a bounded request and uses the same repair path. The existing controlling-input lease remains independent.

The Phaser engineering inspector counts decoded event kinds and displays confirmed shot/hit markers once. It does not play final audio or promote locally predicted effects. Baseline repair restores the currently encoded controller/weapon/enemy/projectile/removal state; complete encounter accounting, allocation/journal state, hostile-threat recovery and campaign terminal baselines still need implementation.

[Browser report](./W04-events-browser.json), [screenshot](./W04-events-browser.png), [clock/browser diagnostics](./W04-events-diagnostics.json).

- Existing movement/lease and same-context controller-session recovery checks pass: 60 shared movement snapshots through tick 180; input neutralization at tick 202 and lease expiry at tick 366 while the room reaches tick 424; recovery from tick 32 resumes all four clients through tick 63. [Controller report](./W04-events-controller.json), [recovery report](./W04-events-controller-recovery.json).

Browser checks used the installed Chromium 151 executable through `EDGEFALL_CHROMIUM_PATH`. The event and abort reports include the actual bundled Worker SHA-256 as well as the client bundle hash and base commit; the portable report records all imported source hashes and runtime versions. The baseline/consumer fault injections are application-level diagnostics in an owned loopback process. They do not claim TCP record reordering or a complete packet-loss, browser-visibility or WAN impairment matrix.

The stalled reader deliberately retransmits a growing retained suffix before repair. This is bounded, but replay traffic and event-frame overhead still require representative busy-room bandwidth/CPU measurement. No steady-load budget, remote trace ingestion, staging soak, production membership, final audio/style or durable combat-recovery gate is closed by these short local runs.

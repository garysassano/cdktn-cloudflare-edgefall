# Authoritative material-room integration

The 64 material calibration scenarios now run through the same constructor and simulation step in the inspector and authoritative diagnostic room. They cover eight action families, four surfaces and stationary/patrolling targets. Snapshots carry an explicit registered scenario ID that remains valid after cover destruction; clients no longer infer terrain from surviving entities. Calibration enemy definition 5 permits 32 HP while ordinary infantry retains its existing health contract.

Solo through four-player baselines have matching player, acknowledgment and encounter rosters. A new diagnostic party-size binding exposed an admission gap: requests for absent slots were still accepted. Both admission and direct WebSocket upgrade now reject those slots, and recovery rejects a stored party size or scenario that differs from deployment configuration.

[Archive 17](../combat-checkpoint-v17.md), combat simulation/recording 14, Breakwater mission/recording 5 and material-inspector recording 2 reject older experiments. [Protocol 3.14](../protocol-v3.md) uses combat section 5 with a 56-byte header and a 53,088-byte maximum complete snapshot. Input, acknowledgment and 96-byte event records retain their layouts. An independent Python `struct` packer checks five combat goldens, including the steel/laser scenario.

The network subset verifies one accepted action per player and retained scene identity through immune cover, damaged cover and destroyed cover. Every player keeps three lives. It does not cover all 128 network combinations, general packet impairment, physical controllers, production recovery or deployed cadence. The complete 128-case matrix belongs to the portable and SQLite checks.

Five network attempts entered recovery because workerd observed time moving backwards, at ticks 10, 161, 33, 98 and 62. None reported a simulation or persistence failure. The clock guard remained intact. Successful cases were resumed only after verifying their source and bundle fingerprints; failed attempts remain in [the controls](material-room-2026-09-08/controls.json). These functional passes do not close the existing host-clock/timing gate. A harness attempt also used Node fetch for an unsupported Upgrade header and was corrected to make a real HTTP upgrade request. Another attempt overlapped the full-check client rebuild, removing its generated bundle before final verification; browser build jobs were subsequently serialized. The stale protocol-minor event assertion is retained as a failure control too.

These are whole-suite elapsed times, not deployed tick CPU measurements.

# Miniflare image-decoder dependency repair

2026-09-09: GitHub reported high-severity advisory [GHSA-rgj7-g3m4-5g8c](https://github.com/lovell/sharp/security/advisories/GHSA-rgj7-g3m4-5g8c) in Miniflare's development dependency `sharp@0.35.2`. The project already used `sharp@0.35.4` directly for its asset tooling; Wrangler 4.128.0 brought a second, affected copy through `miniflare@5.20260831.0-alpha`. The advisory concerns libheif decoding of untrusted input and identifies Sharp 0.35.4 as patched.

A scoped `miniflare>sharp` override in `pnpm-workspace.yaml` makes Miniflare use Sharp 0.35.4 and libheif 1.23.2. The lockfile now has one Sharp version and removes the older native packages. No direct package versions, tool versions or release-age policies change. Registry inspection found that even current Wrangler 4.130.0's Miniflare 5.20260908.0-alpha still pins Sharp 0.35.2, so upgrading Wrangler alone would retain the affected dependency. Remove the override when upstream adopts a fixed version.

Validation passes `pnpm install --frozen-lockfile` and `pnpm check` with 940 tests across 83 files, including unchanged art/audio/content exports and the Worker dry build. A separate local Miniflare Images binding decodes an 8×8 benign AVIF through the patched library, resizes it to 4×4 PNG and verifies all 48 RGB channel values. The probe resolves Sharp from Miniflare's own dependency path and checks its actual Sharp/libheif versions. It adds no game asset or production binding.

The [retained report](./sharp-2026-09-09/report.json), [verification program](./sharp-2026-09-09/verify-miniflare-sharp.mjs) and [artifact manifest](./sharp-2026-09-09/artifacts.json) include configuration/lockfile fingerprints, the image result and compressed check/install logs. Run the probe from the repository root with `node docs/redesign-evidence/sharp-2026-09-09/verify-miniflare-sharp.mjs`. The existing development-only `stream-json` advisory through CDK Terrain remains tracked separately; this change does not resolve it.

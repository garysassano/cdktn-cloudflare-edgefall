# W03 exact swept collision queries

Status: the platform-neutral narrow phase is implemented in `src/game/physics/sweep.ts`. W03 is in progress; the active v2 game has not been switched to this query. W02's failed bandwidth/local timing gates remain open and still precede final controller acceptance.

`sweepAabb` handles a world-space moving AABB, axis segment or point against a positive-area AABB. It subtracts the target's tick displacement before the slab query, so a moving hurtbox crossing a projectile path can be detected. Contact times remain integer numerator/positive-denominator pairs. The query distinguishes strict initial overlap from impact, accepts inward contact at tick start and contact at tick end, and rejects separating or tangent boundary touches. A corner entry retains both axis normals; a corner-only graze does not become a hit. This is a query, not an overlap correction or movement solver.

`sweepOneWay` accepts only a downward crossing in relative space when the body's previous bottom was on or above the platform top. It requires strict horizontal overlap at the rational contact time. `earliestSweep` compares solid and one-way candidates together, retains every equal-time contact, and orders by stable entity ID then X/Y normal. Ignoring a selected one-way ID does not ignore lower platforms or solid terrain. The caller receives initial overlap IDs separately and must handle that invalid/recovery state before applying movement. Candidate counts are capped at 4,096, IDs must be unique, and unsupported terrain fails explicitly.

All coordinates and rectangle edges are checked against ±2^24 subpixels; tick displacements against ±2^16. Edge separations are at most 2^25, relative displacements at most 2^17, and rational comparison products at most 2^42. The one-way horizontal expressions sum terms bounded by 2^42, staying within 2^43. `displacementAtContact` multiplies at most 2^16 by 2^17 and rounds each component toward its starting point, never beyond the exact contact. It does not itself resolve sliding, platform carrying, crush or repeated-contact residual motion. Shapes use authoritative geometry, with no dependency on render textures, browser clocks or framework physics.

## Validation

Eleven tests cover one-subpixel-wall tunnelling, wall-before-target ordering, point projectiles, corner manifolds and insertion-order independence, tangent/separating contact, starting overlap, opposing target motion, maximum coordinates/motion, invalid inputs, signed conservative rounding, upward/downward one-way behavior and selected-support drop-through. The seeded test compares 256 independently reproducible inputs against a test-only BigInt rational oracle, then checks translation and horizontal reflection invariance. A failed seed includes its full input geometry and motion in the assertion; an automated failing-seed minimizer is still required.

The [runtime report](./W03-sweep-runtime-proof.json) records identical results from Node 24.20, Chromium 151 and local workerd through Wrangler 4.128. The 256 seeded inputs contain 23 solid impacts, 10 strict initial overlaps and six one-way impacts, plus an explicit tied-contact fixture. Existing full-snapshot byte/state and processed-command conformance runs in the same command. The report's commit is the pre-change base; its source and bundle digests identify the tested code. This is narrow-phase parity, not a 20-minute gameplay replay or Firefox/WebKit/deployed-Worker acceptance.

`pnpm check` passes 145 tests across 16 files, lint, asset/content validation, all TypeScript targets, client/Worker builds and CDKTN synthesis. `pnpm test:contracts` passes using the existing local Chromium executable override. No production bindings, media, infrastructure or dependencies changed for this addition.

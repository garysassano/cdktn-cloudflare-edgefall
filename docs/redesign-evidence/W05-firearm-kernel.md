# W05: firearm timelines, swept hits and combat inspection

The shared game code now executes firearm action timelines and swept ballistic hits, and the combat inspector connects those modules to real foot movement, supported patrol targets and the encounter lifecycle. This is progress toward W05; production gameplay remains v2 and the complete four-player combat/vehicle gate is open.

## Ownership and tick phases

`src/game/combat/timeline.ts` derives the pose from authored tick exposures and executes markers through the serialized `nextMarkerIndex`. Restoring a consumed marker does not execute it twice. Skipping an unprocessed marker throws instead of silently losing or backdating a gameplay effect. Equal-tick markers retain their authored order.

`firearm.ts` merges onset and held intent into one action attempt, assigns one world-owned action ID/shot ordinal and debits ammunition once. The engineering sidearm uses an eight-tick cadence; HMG uses five ticks and falls back to the unlimited sidearm at the next eligible action after depletion. Rejected tap intent is not queued for later. Death, hurt, melee/grenade and seat transitions take precedence. Changing aim or crouching during fire selects an authored pose variant with the same marker schedule, preserving action ID, start tick and consumed cursor. Fire does not freeze locomotion.

The integrated tick first advances locomotion, then evaluates action markers at the resulting boundary. New projectiles appear at that boundary's authored muzzle and begin motion on the following tick. Existing projectiles sweep against target hurtboxes from their previous to current positions, using the pose selected for the current tick. Damage intents are collected against that phase's living targets and ordered by exact contact time, action ID, projectile ID and collider ID. Simultaneous hits cannot award the same kill twice. Encounter resolution follows actual terminal damage or physical removal; rendering never completes a kill or opens the encounter.

`projectile.ts` queries terrain, shields and body hurtboxes together using the existing bounded rational slab kernel. Earliest contact wins; equal-time contacts prefer terrain, then shield, then body, then stable collision ID. Allied targets and the owner are excluded. This initial ballistic policy consumes the projectile at its first hit, so overlapping body shapes cannot grant duplicate damage. One-way platforms also block bullets as full authored terrain volumes in this policy. The hand-to-muzzle sweep checks the terrain's end pose, preventing a barrel from spawning a shot beyond a thin wall. A projectile receives its authored number of motion intervals after birth and retires after the last one. Explosion, penetration and sustained-volume rules are separate required work.

## Inspector and reproducible evidence

Run `pnpm dev:lab`, then open `/combat-lab.html`. Select range, wall or shield and one to four deterministic input slots; slot 2 has the HMG. Control slot 1 with arrows/WASD, Space and Z. Other slots can hold fire. Enter advances one tick; the buttons run, pause, reset, replay and export/import the recording. Focus loss clears held/tap intent, repeated keydown cannot resurrect it, and recordings are bounded to 3,600 ticks. Import reconstructs from initial state and compares the final canonical state before accepting the recording.

The surface displays exact colliders, hurtboxes, muzzle sockets, shields, projectiles and impact locations. The state inspector exposes action IDs, marker cursors, ammo, damage identities and encounter kill credit. This is one local browser with deterministic input slots, not four network clients. The graphics and silent sound-marker inspection are explicitly engineering media; no final asset or audio claim follows.

# W02 four-client protocol workload

Status: the bounded local four-WebSocket workload and control leases are implemented. Direct workerd completed the synthetic lifecycle checks; the Wrangler path fails the scheduler gate, and both full-snapshot sizes exceed the planned bandwidth budgets. W02 remains open. These diagnostics are separate from the active v2 game and do not implement the future controller or combat.

## Workload and observations

`pnpm bench:room:network --direct-workerd` creates a local Durable Object with four independent Node WebSocket connections using the hibernation API. Every client validates the strict v3 handshake, decodes full binary snapshots, checks the world digest and monotonic delivery/processed-command cursors, and acknowledges received baselines. Clients submit fresh neutral commands for two seconds, then directional/fire intent and one jump/fire-onset edge. The fixture explicitly rejects unsupported actions while still acknowledging the processed edges. It uses simple bounded integer translation to expose input effects, not collision, projectiles hitting enemies, damage or actual controller prediction.

After four seconds the first client stops generating commands but continues acknowledgment-only frames and reading snapshots. The other three stop commands after five seconds. The input stream neutralizes held intent after 250 ms; the new `ControlLease` expires after three seconds without fresh accepted commands, closes the controlling socket and cannot be revived by a late command. Acknowledgment-only, duplicate and stale admissions do not renew it. Once every lease expires, the room pauses with no frame timer or watchdog. The observer checks another 300 ms without tick/callback progression. This is an input-silence experiment, not an actual browser visibility event or TCP packet-loss experiment.

The fixture contains every currently declared snapshot section. The 2× variant doubles non-player population while retaining the required four players:

| Section                                              | Populated fixture |   2× fixture |
| ---------------------------------------------------- | ----------------: | -----------: |
| Players                                              |                 4 |            4 |
| Vehicles                                             |                 4 |            8 |
| Enemies                                              |                32 |           64 |
| Projectiles                                          |                96 |          192 |

| Full snapshot bytes/client                           |            11,352 |       21,288 |
| Nominal application payload at 20 snapshots/s/client |      221.72 KiB/s | 415.78 KiB/s |

Both snapshots exceed the 6 KiB p95 target, and both nominal payload rates exceed 120 KiB/s/client. These figures count codec payload before WebSocket framing or any negotiated compression; they are not billed egress measurements. The budgets remain failed. Do not reduce the population to make the report green; measure compact common entity fields, per-client controller precision and acknowledged deltas/coalescing before selecting a steady snapshot format. Full recovery baselines and normal steady traffic can have different roles, but the final prediction/recovery contract must stay complete.

The [direct workerd trace](./W02-network-direct.json) records both 480-tick runs, independent receipt/host-clock samples, local callback/deadline data, bounded input queue maxima, processed-edge acknowledgments and lease transitions. Both runs used at most one queued command per client and recorded no receipt gap above 100 ms across 612 gap samples per workload. The synthetic tick-duration p99 was approximately 1–2 ms on the recorded Ryzen workstation; local runtime clocks are quantized, zero means below their observed resolution, and this is not a CPU profile of the missing gameplay kernel. These eight-second runs do not establish five-minute cadence windows, release-soak behavior or a memory plateau.

## Local scheduling discrepancy

The identical full workload through `pnpm bench:room:network` repeatedly enters recovery within its first few ticks. The [recorded Wrangler failure](./W02-network-wrangler-failure.json) preserves requested/fired timers, callbacks, independent observer clocks, peer counts and partial receipts. The scheduler's 250 ms debt guard is retained; changing the language or suppressing the guard would not explain this observation. An earlier direct 2× run also observed a backward clock jump at tick 453; that [failure](./W02-network-direct-regression.json) is retained rather than discarded. Its failure-record timestamp precedes its last Node wall-clock sample, and a separate [read-only host time-sync observation](./W02-host-clock.json) records a large negative offset. This identifies host-clock instability as an additional limitation. No clock configuration was changed. Successful short runs therefore cannot establish reliable cadence on this host; repeat the gates on a stable reference environment.

`pnpm bench:room:timers` removes all Edgefall code, simulation, codecs and snapshot sending. Its inline Worker requests native recursive `setTimeout(1000 / 60)` callbacks for HTTP-only, classic-WebSocket and hibernation-WebSocket controls. Each run is bounded by 60 callbacks and a watchdog, and the observer stops it explicitly after 1.6 seconds. Classic sockets are only a diagnostic control; hibernating sockets remain the required game API.

| ------------------------------------------- | ------------------: | --------------------------: | ------------------------------: | ------------------------------------------- |
| Direct installed workerd                    |                  60 |                          60 |                              60 | [Trace](./W02-native-timers-direct.json)    |
| Direct installed workerd, inspector enabled |                  60 |                          60 |                              60 | [Trace](./W02-native-timers-inspector.json) |
| Wrangler dev                                |                  60 |                          60 |                               8 | [Trace](./W02-native-timers-wrangler.json)  |

The Wrangler hibernation control exhibits growing callback delays despite the absent game workload. Its independent Node wall-clock increments stay within roughly one millisecond of monotonic elapsed increments. This isolates an observed local launcher/hibernation-path discrepancy and rules out Edgefall simulation as a necessary trigger; it does not identify a specific upstream line or prove behavior on deployed Cloudflare. Merely enabling an inspector port in direct workerd did not reproduce it. `bench:room:timers` collects comparison data rather than asserting a production cadence gate; its successful exit is not timing acceptance. Use `--wrangler` or `--inspector` for the other controls.

The initial discrepancy reproduced with Wrangler 4.127/workerd 1.20260826.1 and remained after `pnpm up wrangler@latest` selected 4.128/workerd 1.20260831.1. The project's strict 4,320-minute release-age policy excluded the newer 4.129 release at execution time; it was not bypassed. The current lockfile and generated Worker declarations reflect 4.128. The attached final comparisons use the same installed versions and source hashes. No upstream message or deployment was published by this investigation.

## Bounds, provenance and remaining gates

Validation for this addition: `pnpm check` passes 134 tests across 15 files, asset/content validation, all TypeScript targets, browser/Worker builds and CDKTN synthesis. `pnpm types` regenerated the runtime declarations for workerd 1.20260831.1; production binding names are unchanged. `pnpm test:contracts` still produces matching Node/Chromium/workerd bytes and input traces, and both existing real-browser baseline tests pass with the documented Chromium executable override. These regressions do not override the explicitly failed bandwidth/local timing gates above.

The load fixture accepts only loopback hostnames, two fixed room names and four controlling slots. Each room has a 20-second watchdog, 1,200-tick cap, bounded callback/timer/CPU traces and bounded input histories. Snapshots are suppressed after 500 ms without advancing delivery acknowledgments; a persistently stalled reader is closed at one second. The lease experiment keeps delivery acknowledgments flowing so reader backpressure does not mask control expiry. Reader-stall closure is implemented but still needs its own end-to-end impairment case. Process/object reconstruction deliberately closes old diagnostic sockets instead of pretending their in-memory input histories were recovered; real storage/replay recovery remains required.

Every runner owns its local runtime and closes it in `finally`. Network failures are written to timestamped local artifacts before propagating the failure. Report source hashes cover the relevant source graph and runner/configuration; `baseCommit`, where present, is the commit before the tested additions. The earlier regression trace has an earlier source hash; the final runner additionally records a host clock sample in its failure handler. None of these files contains credentials or production data.

Remaining W02 work includes raw editor compilation and immutable build identities, renderer stress, actual browser visibility/focus transitions, stalled readers, storage/reconstruction, and a bounded staging workload/cost/abort proposal. Replace synthetic motion with the W03/W05 world and profile allocation/GC and world-plus-encode work before final acceptance. Remote cadence, two-hour staging/six-hour release soaks, physical-host/network impairment and all human visual gates remain open.

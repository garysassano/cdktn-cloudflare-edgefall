# Local firearm feedback and mixed-action recovery

The diagnostic network client now shows foot firearm muzzle feedback from pending input before the room acknowledges it. Prediction shares the movement and foot-action kernel, including cadence, ammunition fallback, grenade priority and contextual melee arbitration. The renderer promotes the same cosmetic marker when authority confirms it, corrects its position/material result and preserves its age. Replaying pending input creates no presentation callbacks. Damage, inventory grants and gameplay events remain authoritative.

The bounded ledger uses run/player/control generation, shot ordinal and marker index rather than predicted global action IDs. It covers all six foot guns, including the three flame emission markers. The 100 ms visual lifetime uses browser monotonic time. Rejection waits for both processed input and its complete snapshot-paired event prefix; replay cancellation, baseline repair and fresh connections discard uncertain cosmetics. The public event and archive layouts remain protocol 3.14 and archive 17.

The initial laser browser run exposed a pre-existing persistence mismatch at tick 69: physical Fire-before-Jump was valid on the wire but the combat journal demanded ascending edge kinds. Journal validation now preserves arrival order across kinds and validates independent per-kind ID counters. This fixes a real mixed-action room failure without sorting input, changing action priorities or relaxing the scheduler guards.

Two implementation/verifier failures are also retained: the first unit test caught promotion resetting the first acknowledgment timestamp, and the initial material preload counted a destructible as both terrain and a damageable solid. Both were corrected. A flame run against an armed laboratory target lost lives while firing upward; the feedback matrix therefore uses existing stationary material rooms to measure the intended behavior. These successes do not claim survival acceptance against the hostile flame encounter. A later laser run stopped on workerd time regression at tick 20 without simulation/storage failure; its trace remains in the package. The final case resumed only after rebuilding and verifying current source/bundle fingerprints for earlier passing cases.

Browser jobs that rebuild `dist/client` must run sequentially. The local harness uses the installed Chromium selected by `EDGEFALL_CHROMIUM_PATH` and does not require a Cloudflare deployment.

# W04 — Authority-issued controller session recovery

The loopback controller room can now replace an invalid input session without rebuilding its world at tick zero. A bounded observer-triggered `POST /controller/recover` constructs and validates the replacement before closing the old clock/sockets. It preserves the last completed simulation tick, physical bodies, health and campaign state; increments run, connection and control epochs; clears old acknowledgment/edge cursors and buffered jump intent; and returns to loading. Old queued commands belong to the invalidated generation and are discarded, not reported as applied. The room waits for all four replacement connections and five fresh input ticks per client before issuing its playing boundary and restarting the clock.

Recovery is limited to four observer requests per local room instance and rejects terminal/loading states. Vehicle occupancy is rejected because this controller fixture does not own vehicle handoff. A runtime restart still closes old sockets and requires the future durable recovery implementation; this change does not invent persistence from a new empty world. The production Worker does not export this diagnostic route.

The browser validates the complete first snapshot against the decoded welcome: run/connection/player identity, exact snapshot ID and tick, event baseline, entity ID and fresh acknowledgment cursors. It installs capture/prediction only from that pair. After a socket closes, a visible reconnect control reloads the client session; it can reconnect once the server has prepared the replacement baseline. No client chooses its own tick mapping or silently relabels old input with the new epoch.

The final preload is five ticks, leaving one tick below the unchanged six-tick admission ceiling. A [later six-tick-preload run](W04-recovery-admission-failure.json) rejected one client's startup input; its [client state](W04-recovery-admission-clients.json) is consistent with crossing that ceiling, but the old probe discarded the exact rejection reason. Peer diagnostics now retain a bounded admission error message. A controlled input-stream test proves that, with five preloaded ticks, one additional command can arrive before the first room tick, while a seventh remains rejected. This is headroom, not a cadence guarantee.

## Validation

Six recovery tests verify immutable world preservation and epoch rotation, exact welcome/baseline matching and rejection cases, binary baseline installation at tick 47 with the next fresh command applied at tick 48, rejection of old-run packets without acknowledgment advancement, atomic failure for exhausted counters/unsupported vehicle ownership, and one tick of startup headroom without weakening the six-tick admission ceiling. `CHECKPOINT_DISABLE=1 pnpm check` passes the full suite of 308 tests across 30 files and all other required checks.

Run `EDGEFALL_CHROMIUM_PATH=/path/to/installed/chrome pnpm test:network:controller --recovery` to exercise the local flow. The [earlier retained browser report](W04-recovery-browser.json), before the final five-tick preload change, passes with four real WebSocket clients. The authority pauses at tick 32, closes all four old sockets with `baseline-replaced`, and issues run epoch 2. The verifier clicks the reconnect control in the same four browser contexts, verifies fresh counters and baseline tick 32, proves a premature start is rejected before input preload, then resumes. All four clients receive tick 63 without full-controller corrections; the final observer status is tick 65 with no clock fault. [Host/browser diagnostics](W04-recovery-diagnostics.json) and the [inspected engineering screenshot](W04-recovery-browser.png) accompany that result. The deterministic input script follows the preserved world tick after reconnect, even though command/edge counters restart; it does not replay its opening movement from tick zero. The report's base commit identifies the checkout before this change was committed; its client bundle digest identifies the tested build.

The final five-tick-preload browser run [fails after reconnection](W04-recovery-current-failure.json), despite completing epoch rotation and fresh preload. Run epoch 2 reaches tick 40; slot 1 stops on an unacknowledged command overlapping the restored tick-39 snapshot. [Client receipts](W04-recovery-current-clients.json), [host/browser diagnostics](W04-recovery-current-diagnostics.json) and the [failure screenshot](W04-recovery-current.png) preserve this result. The room has no clock fault and no recorded admission error in this run. The earlier successful report is not substituted for final-source acceptance. Keyboard auto-repeat is now ignored after blur/reconnect, and the verifier includes a real keyboard repeat/neutralization check; the complete final browser scenario remains failed.

This short recovery scenario is separate from the default movement/action/lease verifier and does not replace its previously captured timing failure. It does not prove automatic reconnection, durable restart/rewind reporting, in-place control/seat handoff, campaign recovery, gamepad lifecycle, impaired transport, physical input latency or live Cloudflare cadence. The host-correlated clock regressions in `W04-input-capture.md` remain open evidence. W04/G2 and the full redesign are not complete.

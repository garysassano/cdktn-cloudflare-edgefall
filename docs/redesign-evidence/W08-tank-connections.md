# W08: tank connection handoffs

The authoritative diagnostic room now accepts a connection replacement while its player owns a tank. An obsolete admission guard previously returned HTTP 409 for every seated player before the existing safe handoff could run. The room now reaches that handoff, which releases both ownership links, advances the player's control generation and supplies an unseated baseline. The connection-generation exhaustion guard remains in place. This change affects the diagnostic room; production protocol v3 integration remains separate work.

The new four-browser verifier uses actual profile cookies, WebSockets and keyboard input. P1 keeps its primary trigger held while another tab takes over. The retired tab stops retrying, its close is fenced, and its held input cannot keep firing the released tank. P2 exits its original tank, walks to P1's abandoned hull, claims it and drives while firing. Disconnecting P2 neutralizes held movement and fire, retains the seat for the configured grace period and then releases it safely. P2 returns in the same document with a new connection baseline while the other players keep advancing.

P3 and P4 remain seated until all four connections leave. The empty-room boundary settles those seats and persists the complete world without ticking through disconnect grace. A fresh local workerd instance opens the same SQLite state and service origin. Four ordinary reconnects restore the frozen world with renewed input generations and no historical effects. Starting without fresh input is rejected; preparing each browser permits play to continue.

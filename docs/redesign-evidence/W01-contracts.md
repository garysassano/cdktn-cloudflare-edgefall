# W01 arcade contracts

Status: in progress. The first contract implementation establishes fixed arithmetic, domain state/content types, a validated engineering fixture, binary input and acknowledgment codecs, and strict content/build handshakes. The old v2 game remains the active runtime until a coherent replacement can run. These definitions do not claim a completed controller, vehicle, mission, or v3 room.

## Decisions

The candidate composition is 384×216 logical pixels. Positions/velocities use Q256 subpixels and ticks use the candidate 60 Hz rate with 20 Hz snapshots; W02 must prove the actual room cadence before acceptance. The contract operative stands 34 pixels tall physically, with a 14-pixel body width and a smaller hurt shape. The initial 3-pixel/tick run speed, -1430-subpixel jump velocity and 55-subpixel/tick gravity are calibration values in the engineering fixture. Final silhouettes, poses and motion tuning remain subject to the benchmark.

Default direction is arrows or WASD. Fire is J/Z, jump is Space/K/X, grenade is L/C, interact is E, and vehicle special is V. Standard gamepad mapping uses A for jump, X for fire, B for grenade, Y for interact and LB for vehicle special. Opposing directions cancel while retaining facing; down crouches on ground and requests downward aim in the air. A separate interact avoids ambiguous multiplayer boarding, and vehicle sacrifice requires a separately held action. Remapping UI and input capture are W04/W13 work; the legacy UI has not silently been relabeled with unsupported controls.

Classic uses one infantry health pip, three lives including the current life, ten grenades, three tank armor pips, and three shared campaign continues. Accessible is a separate declared/recorded preset with three infantry health pips and nine shared continues. On death, decrement once, discard the special weapon, and only respawn with positive remaining lives at a validated checkpoint with 120 ticks of protection. A zero-life member gets one rally life at the next mission transition, once per transition. Host-authorized continues reset the checkpoint and participating players' lives/equipment; reconnect never replenishes lives. These are explicit game rules to implement, not inherited v2 operator statistics.

Use one tank per participating player in the mission-one depot and one aircraft per participant in the required flight section. On contested individual pickups, earliest contact then player slot decides one claimant. On contested vehicle interaction, valid command order then slot decides one driver. The driver and vehicle keep separate IDs and each authority transfer increments control epoch. No friendly fire or player-body blocking. The controller state carries support, ignored support, contact fractions, integer timers, weapon ordinal, action instance/marker cursor, seat, geometry revision and edge cursors for future exact reconciliation.

## Implemented boundaries

`src/game/core` enforces coordinate/motion/counter bounds, signed truncation with retained remainder, rational-contact comparison within the documented 2^43 product bound, seeded Xorshift32, canonical integer state serialization and a diagnostic FNV-1a hash. The diagnostic hash is not an authentication primitive; `pnpm content:validate` uses Node SHA-256 over canonical compiled content. Content identity includes collider/pose/socket/timeline definitions and excludes atlas packing. Identity format, simulation version/build, protocol version, checkpoint format, replay format and presentation build are independent.

`src/game/input` owns domain intent and canonical applied-tick journal types. Missing-input repetitions cannot repeat edge actions; external neutralization, connection, geometry, seat and recovery decisions must be journaled at explicit ticks/orders. Derived changes are replay assertions rather than a second application of the same cause. The server-side queue and replay adapter still need to enforce this contract.

`src/shared/protocol` implements the [v3 input and acknowledgment format](../protocol-v3.md). The handshake rejects simulation, content or required presentation mismatches before readiness; a deployment build ID may differ if compatible identities match. No arbitrary legacy input JSON is accepted by the new binary decoder.

The fixture links standing/crouching/hurt/projectile shapes, operative/tank poses, muzzle/hand/seat/ejection sockets, fire/boarding timelines, sidearm, actor movement, vehicle seat, solid floor, one-way platform and encounter/checkpoint data. It is labelled engineering content. Validation catches invalid references, exposure durations, marker times/sockets, numeric bounds, duplicate stable IDs, absent visible-surface identity and missing ejection candidates. It validates typed compiled content; W02 must validate untrusted editor JSON and actual navigable/spawn/exit geometry at compilation.

## Evidence and remaining gate

Forty-six new tests pass across two files, including independently packed 32/52/92/284-byte input goldens, the 40-byte acknowledgment golden, every truncated input prefix, reserved/count/mask corruption, epoch mismatches, counter rollover, 1,000 deterministic generated/fuzz cases, canonical-state and arithmetic vectors, directional arbitration and invalid content mutations. Node, browser and Worker typechecks include every shared contract file. The current engineering content SHA-256 is `29ae37575304a2e729e0c284e60cdeb2df4f8fdfeb8da4c596b4821d16b380e2`.

W01 remains open for full snapshot-section framing/goldens and executable processed-command/edge sequencing contracts, including immutable duplicate detection and explicit no-op acknowledgments. W02 must add the editor compiler and generated build identities; W03/W04 must consume these definitions in an actual deterministic controller/room with complete prediction. No runtime art production or live feasibility gate is closed by this work.

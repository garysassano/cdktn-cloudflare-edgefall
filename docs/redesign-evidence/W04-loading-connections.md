# W04 durable connection replacement during loading

A reserved player can now replace either a connected or a disconnected socket while the combat laboratory is loading. Previously, admission preflight accepted the owner but the WebSocket route rejected every slot already present in the peer map. The replacement now persists a fresh connection generation at the same combat tick before sending its welcome. This extends [empty-room recovery](./W04-empty-room.md); production authority remains v2.

## Implemented boundary

The replacement advances only the selected player's connection epoch and clears their old command/edge acknowledgment and buffered jump intent. It preserves the run epoch, control ownership, ammunition, active firearm action, health, lives, projectiles, encounter accounting and retained event history. Other players keep their input streams and queued commands. The new reader must acknowledge its own welcome baseline and preload fresh input before the start barrier can admit it.

The loading transition excludes concurrent starts and admission mutations while its checkpoint is pending, ignores the old socket's input during that interval, and rechecks the room phase after persistence. Installation registers the replacement before retiring the previous peer, so its delayed close cannot evict the new generation or cause an empty pause. A persistence failure requires room recovery. Checkpoint replacement validates the preceding durable hash, writes checkpoint/head together, prunes superseded segments and awaits write confirmation before welcome, using Cloudflare's [SQLite transaction and sync contract](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/#transactionsync).

## Validation

- `CHECKPOINT_DISABLE=1 pnpm check` passes 414 tests in 42 files, lint, all TypeScript targets, content/assets, production client/Worker dry-run build and CDKTN synthesis. The new pure checks preserve a special weapon during an active action, validate the snapshot after every waiting connection is replaced, and reject wrong phases, unknown owners, exhausted generations and unsupported vehicle handoff. The environment flag bypasses optional CDKTN telemetry. [Check output](./W04-loading-check.txt.gz).
- `pnpm test:storage:combat` replaces player 2 at tick 45 in run epoch 2, advancing its connection from 3 to 4 without changing the other owners. A fresh workerd process restores the same tick, epoch and hash `065e20c2`. Injected checkpoint failure rolls back, and a second replacement using the stale preceding state is rejected without mutation. Earlier journal, short-tail, pause and expiry checks also pass. [Storage report](./W04-loading-storage.json).
- `pnpm test:network:controller --combat-loading` uses four real Chromium contexts and selects the actual host by membership identity. In the final run, slot 1 replaces a connected tab and then reconnects from the same replacement document after disconnecting. Its connection epochs are 2 → 3 → 4, with combat and clock held at tick zero. Its previous five-command preload is discarded each time; the other three players retain five queued commands. The disconnected host transfers to slot 2 and does not reclaim the role on return. Wrong-slot admission and an attempted start before the replacement's fresh baseline/preload both return 409. [Browser report](./W04-loading-browser.json.gz), [independent diagnostics](./W04-loading-diagnostics.json.gz).
- The same browser scenario then passes playing takeover, disconnected reentry, fresh-baseline rejection, retained kill credit and healthy-peer continuation through room tick 278, with seventeen matching snapshots and zero movement correction. A new process reconstructs committed tick 270 in epoch 2 after the journaled replacements. This is the existing bounded committed-prefix recovery behavior, not an exact-tick guarantee for arbitrary process loss.
- The automatic-reconnect regression also passes on the same Worker bundle. It confirms empty pause tick 185/hash `19d6c94a`, restores that exact tick through ordinary reserved admission in epoch 3, and matches fifteen snapshots through tick 222. Solo return starts at 287 and progresses through 312. A real alarm delivers once and expires tick 314 in epoch 4, which another process reloads as terminal. The observer waits 100.1 seconds; the configured reservation deadline remains ninety seconds after the durable membership timestamp. [Automatic recovery report](./W04-loading-auto.json.gz), [diagnostics](./W04-loading-auto-diagnostics.json.gz).

Reports identify pre-commit base `fcb5ba6`, Chromium 151.0.7922.34 and the tested bundle. The [artifact manifest](./W04-loading-artifacts.json) pins source and original/compressed SHA-256 hashes. Two earlier verifier assertions assumed slot-ordered connection arrival and a zero replacement count before the playing scenario. Both were corrected without changing simulation guards; [derived failure notes](./W04-loading-verifier-notes.json) preserve the observed states. No runtime clock or persistence fault was reported in those attempts. The earlier [host-clock failure](./W04-empty-room.md#preserved-failure-and-remaining-work) remains unresolved; short passing runs do not close sustained timing acceptance.

## Remaining work

The signed membership claim and combat checkpoint remain separate lifecycle writes. This does not prove atomic production admission, uncertain commit recovery across every interleaving, result outbox or retention cleanup. Loading replacement is proven for on-foot owners; vehicle ownership and protected hostile reentry still need their own behavior and acceptance tests.

The laboratory still begins in its loading fixture and uses explicit start/recovery controls. Full lobby/intermission/completed-phase admission, high-entropy production room capabilities and membership-epoch host commands remain required. Production v3 integration, prediction/effects, network impairment and visibility tests, sustained runtime/renderer/bandwidth/cost gates, hostile combat and the full three-mission campaign remain open. W04/G2, W05 and W10 are not closed; the W06 human style review still precedes remaining final asset production.

Wrangler retains explicit tracing and invocation logs at sampling 1 plus source-map upload. This increment does not deploy or retrieve live traces; deployed ingestion and performance remain unverified.

# W04 individual combat reconnect and ownership

One player can now replace a socket or rejoin the running combat laboratory while the other players continue in the same run. A signed anonymous browser profile owns the reserved slot, the authority journals the connection transition, and the replacement acknowledges a fresh snapshot/event baseline before its input is admitted. The four-browser proof also reconstructs the journal in a fresh workerd process. Production remains v2; this is a bounded integration milestone within the full redesign.

## Implemented boundary

The gateway and laboratory share the existing UUID/expiry/HMAC profile-cookie format. Verification rejects tampered signatures, expired claims, duplicate cookies, noncanonical encodings and oversized input. The laboratory accepts only loopback requests and loopback browser origins, generates profiles through an HttpOnly cookie, and overwrites the internal profile header. Its status endpoint and evidence omit profile IDs and credentials. The owned direct-workerd harness generates one temporary signing key and retains it across its process restart.

Private SQLite membership records contain at most four profiles with slot ownership, socket generation, join ordinal, membership epoch and reservation deadline. Disconnect reserves the existing slot for ninety seconds. Strangers cannot enter a running mission, and one profile cannot control a different slot. A stale close cannot release a newer generation. The oldest connected member succeeds a disconnected host; rejoining does not reclaim that host position. These host fields are metadata for the laboratory, with production host-command authorization still open. Cold recovery uses the last persisted heartbeat rather than granting another ninety seconds on each restart.

At the next accepted world tick, the authority replaces only the returning player's input stream and advances its connection epoch once. It discards held intent and edge/command acknowledgment cursors while retaining the control epoch, active action, weapon, ammunition, health and lives. Existing projectiles and encounter accounting continue. Vehicle handoff is rejected until its own ownership policy exists. The transition and neutralization are journaled and replayed through the same evaluator. Other peers retain their queues, sequences and event prefixes.

The old socket is retired before the replacement welcome. Initial output contains a full snapshot and mapping without replaying the old event ring. Further output waits for an explicit acknowledgment of that promised snapshot and event cursor; unacknowledged gameplay closes the new connection. Renderer startup completes before the browser requests an active-world baseline, after which it preloads five fresh commands and begins capture. This is manual reentry, with no automatic retry/backoff or transport generation manager yet.

## Preserved failure and remaining work

The first live takeover issued its welcome at tick 78, but renderer startup delayed the first input admission until 91. The replacement rejected the next mapping at 93; all three healthy peers continued. Socket creation now waits for the renderer's first frame. In the final run, the returning clients' first admissions arrive at their baseline tick or one tick later. The six-tick lead/drift guards are unchanged. [Failed room](./W04-combat-reconnect-startup-failure.json.gz), [failed client timelines](./W04-combat-reconnect-startup-clients.json.gz), [independent host diagnostics](./W04-combat-reconnect-startup-diagnostics.json). An earlier denial-probe harness failure came from Node fetch rejecting an Upgrade header; those probes now use real HTTP upgrade requests. [Preserved harness failure](./W04-combat-reconnect-harness-failure.json.gz).

Production host-command authorization, high-entropy room admission, automatic reconnect, paused-empty/expiry behavior, protected reentry against hostile attacks, vehicle ownership and atomic membership/result-outbox recovery remain open. Membership admission/disconnect writes are separate from combat segments; their heartbeat shares the combat head transaction. Current run-epoch recovery fences old sockets, but this is not a completed production membership transaction protocol. Predicted actions/effects, the impairment/visibility/soak matrix, deployed timing and the three-mission campaign still need their own evidence. W04/G2, W05 and W10 remain open, and the W06 human style gate remains ahead of final asset production.

Wrangler still explicitly enables traces and invocation logs at sampling 1, plus source-map upload. The earlier read-only Cloudflare check found no Edgefall deployment in the accessible account; this change performs no deployment and does not verify live trace ingestion.

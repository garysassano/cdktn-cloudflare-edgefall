# Combat checkpoint and applied-input journal v2

The combat laboratory now has a separate server reconstruction format. It preserves the private simulation continuation that the [3.2 client snapshot](./snapshot-v3.md) deliberately projects: all target bodies and patrol turns, encounter definition/receipts/watchdog timers, current tick notices, allocation/action/marker cursors, players, projectiles, acknowledgments, the retained output event history, and the connected input-owner roster. This format currently supports the existing sidearm/HMG range, wall and shield fixtures. It is not a production campaign checkpoint.

## Identity and bounds

Checkpoint and journal envelopes contain exactly `format: 2`, protocol major/minor `3/2`, kind (`checkpoint` or `journal`), identity, canonical JSON payload and its SHA-256 digest. The identity contains run ID, simulation version/build, content format/hash. Presentation identity is not part of authoritative replay. Every identity must match the caller's expected identity; changed versions, missing fields, noncanonical payloads, corruption and incompatible builds fail before reconstruction. Format 1 and protocol 3.0/3.1 diagnostic archives are rejected. Protocol 3.2 adds the independent `lifeStartTick` to player records and captures firearm marker confirmation metadata before later damage can cancel an action. This does not migrate the production v2 room's storage.

The private continuation now includes `pausedFrom`. It records `lobby`, `loading`, `playing` or `intermission` only while the snapshot is `paused-empty`; every other phase requires `null`. Both checkpoint validation and the runtime hash cover it, so recovery cannot silently turn an empty lobby into a running mission.

The diagnostic content hash is calculated from the actual content and firearm profiles. Its simulation build remains the explicitly synthetic probe identity; no deployed build provenance follows from this fixture. Payloads are limited to less than 512 KiB, and incoming envelopes to 1 MiB of UTF-8. The digest detects corruption and is not authentication or evidence that a simulation was fair.

Capture clones the live state before the first asynchronous digest operation. Checkpoint validation checks the complete snapshot codec and its projection against the private world, the encounter continuation, target life/support, projectile ownership/lifetime, action marker age, allocation cursors and contiguous retained event history. `EncounterLifecycle.restore` checks an existing continuation without advancing its tick or watchdogs.

## Accepted journal

`stageCombatRuntime` evaluates the existing combat kernel and output event staging under the same `InputStream.processWorldTick` transaction used by the conformance fixture. Each `CombatJournalTick` retains normalized `AppliedInput`, original submitted intent when present, edge outcomes, resulting acknowledgment cursors, ordered external decisions, the prior state hash and a resulting state-hash assertion. Missing commands retain their explicit held-repeat/stale decisions. A disconnected input owner is recorded as a connection change and neutralization; stale held input has a distinct neutralization decision.

The current laboratory supports these connection/neutralization boundaries only. Geometry, seat transfer, production membership and campaign transitions need their own implemented external-decision handlers; replay rejects unexplained additional boundaries. Journal replay does not feed old packets back through admission, consult a wall clock, emit client effects, or apply derived kill/damage events twice.

Segments contain one to fifteen consecutive ticks of one run epoch. Replay requires the exact previous tick and hash, reproduces outcomes and ordered decisions, and compares the entire generated journal entry before accepting its candidate. Missing, duplicate, reordered or changed segments fail without mutating the prior state. Per-recipient snapshot IDs and connection header selection are excluded from gameplay assertions; player connection/control acknowledgments remain included. FNV assertions are deterministic diagnostics, while the envelope SHA-256 covers the persisted payload.

The running room captures its already accepted segment boundary before asynchronous work. `encodeAcceptedCombatJournalSegment` verifies the complete prior/result hash chain and validates that boundary, then seals the immutable applied decisions. Only the coordinated authority commit may supply this accepted state. The room does not resimulate fifteen ticks during every write: the earlier two-replay write path was followed by an observed 92 ms timer gap and an input-lead rejection. Loading an archive still resimulates every journal decision and compares its generated outcomes; a changed decision with a valid envelope checksum and unchanged asserted hashes fails reconstruction. The separate `encodeCombatJournalSegment` helper also replays when preparing externally supplied fixture decisions.

## SQLite store and recovery boundary

`CombatStorage` is a laboratory adapter with one exclusive operation at a time. It commits fifteen-tick journal segments and replaces the checkpoint every sixty ticks. One SQLite transaction writes the segment/checkpoint, prunes superseded segments and advances a head record containing the committed epoch, tick and state hash. The store waits for `storage.sync()` before returning a confirmed durable boundary. Loading consumes a bounded database view before asynchronous decoding and requires every segment through that head. The table contains at most one checkpoint, three segments and one head row. The implementation uses synchronous transactions and parameterized SQL. [Cloudflare SQLite storage API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/).

The local storage verifier commits through tick 105 while its observed fixture reaches 119. A fresh workerd process reconstructs exactly tick 105, including both kill credits and the next entity/action IDs. The fourteen later ticks are intentionally absent. Injecting an exception between the data write and head update preserves the previous tick-45 and tick-90 states for checkpoint replacement and segment append respectively; deleting an intermediate committed segment rejects recovery. The verifier uses the installed Miniflare `resourcePersistencePath` option and owns/removes its temporary database directory.

The continuous diagnostic WebSocket room now uses one `CombatJournalWriter`. A synchronous accepted world tick stages its journal entry; the writer starts storage work on a microtask after the clock callback returns and retains at most thirty accepted but unconfirmed ticks. Only one fifteen-tick segment is in flight. Reaching the limit or receiving a failed/mismatched write acknowledgment stops gameplay and closes the input cohort without converting an accepted tick into a clock-step failure. A late successful confirmation may advance the durable cursor but cannot resume gameplay or schedule the queued segment. Recovery retires the writer and reconstructs the latest valid database head. The writer advances its confirmed cursor only after `storage.sync()`; an acknowledgment lost after a committed database transaction can require resolving an uncertain outcome from storage rather than assuming that transaction rolled back.

Active-room recovery persists a replacement checkpoint with incremented run, control and connection epochs before issuing any welcome. Tick, players, physics, weapons, active action/marker cursors, projectiles, private target state and encounter accounting continue from that checkpoint. Old command/edge cursors, buffered jump intent and transient output history are cleared. An empty lobby or intermission returns to its saved passive phase; interrupted loading or combat returns through `loading`. Every currently connected player must acknowledge the fresh baseline and preload five commands before the current host can start; one ready player is sufficient while other slots remain reserved. The loading-to-playing boundary is persisted before the clock starts. Completed results permit reserved-member connection replacement without gameplay recovery; expired rooms cannot resume. Public baseline continuation hashes normalize recovery-owned transport/input fields, preserving weapon/action/physics/encounter values for comparison against earlier snapshots. Archive reconstruction separately checks private AI/watchdog state.

The four-browser recovery verifier replaces an owned workerd process while combat is running, then checks the fresh cohort against its prior public baseline at the restored tick. It separately injects transaction rollback and holds a write until the thirty-tick backlog limit pauses the actual room. Releasing that held write cannot restart the room. Fault injection is loopback-only and the write hold expires after two seconds. Automatic reconnect and empty-room expiry have separate local browser checks. Host power loss, deployed storage latency, complete production membership and the production result outbox remain open. The production Worker remains v2.

## Individual connections

Individual connections can now rotate inside a playing combat laboratory. The accepted tick journals a disconnect neutralization and a connection boundary with the next connection epoch. The replacement begins with no submitted command, held intent or processed-edge cursor. Its control epoch and existing weapon/action/life state continue; other players retain their input streams and the run epoch. Journal replay validates the same transition, including the discarded intent and exact acknowledgment reset. A valid snapshot recipient is selected if the previous recipient's connection epoch has been retired. [Per-player reconnect evidence](./redesign-evidence/W04-combat-reconnect.md).

Private slot ownership lives in a separate bounded SQLite row. New members can enter only in a lobby or intermission; reserved profiles may reconnect to loading, play, an empty pause or completed results within their ninety-second window. Signed profiles cannot claim another slot. Persisted join ordinals, membership epochs and socket generations fence stale closes, including when another profile takes an expired slot. A cold restart uses the last durable heartbeat without extending the deadline. Heartbeats are written alongside combat head transactions; membership admission and disconnect metadata are separate lifecycle writes. Atomic production membership/outbox recovery, campaign phase producers, vehicle transfer and production room capabilities remain open.

The laboratory now begins in `lobby`. Its bounded host-command request carries the action, run epoch, connection epoch and membership epoch; the gateway verifies the signed profile, and the room checks its active socket and host role. `load` and `start` repeat these checks inside the checkpoint transaction and after confirmation. A disconnected host transfers to the oldest connected member and does not reclaim the role on return. Non-host and stale commands are rejected; `continue` and `rematch` remain explicitly unavailable until their campaign reset/publication semantics are implemented. Anonymous `/combat/start` no longer bypasses authorization. [Room phase evidence](./redesign-evidence/W04-room-phases.md).

The life recovery fixture drives four admitted movement/fire streams through actual floor exits. Checkpoints and fifteen-tick committed segments preserve death delays, protected entry, spent lives and shot ordinals; the SQLite verifier injects transaction failures and starts fresh workerd processes during death and entry. Campaign continue/rally helpers only stage candidates for a future atomic world reset. They do not enable host continue/rematch.

## Verification

Run `pnpm test:contracts` for Node/Chromium/local-workerd agreement, `pnpm test:storage:combat` for the owned SQLite restart and transaction-failure proof, `pnpm test:network:controller --combat-recovery` for the running room's restart/write-failure/backlog barriers, and `pnpm test:network:controller --combat-baseline` for encounter repair after missed kill effects. Browser commands need the installed Chromium path through `EDGEFALL_CHROMIUM_PATH` in this workspace. Run `CHECKPOINT_DISABLE=1 pnpm check` for the repository gate; the flag only bypasses optional CDKTN CLI telemetry.

Use `pnpm test:network:controller --combat-phases` for signed host commands, lobby takeover and same-document cold return, followed by loading and playing reconnect regressions. The SQLite verifier independently seeds intermission and completed checkpoints; it does not prove gameplay reaches those campaign phases. `--combat-auto-reconnect` also waits for the real ninety-second reservation expiry alarm. The direct workerd helper generates a temporary signing key and reuses it across its owned restart; the Wrangler diagnostic configuration contains an explicitly disposable local fixture key. Neither is a production credential.
